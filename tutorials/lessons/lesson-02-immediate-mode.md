# 第 02 课：立即模式与每帧 UI

配套程序：`src/tutorial02_immediate.cpp`。本课是全书最重要的心智模型课——
后面所有内容（控件树、函数式库、主题自适应）都建立在它之上。

## §2.1 保留模式 vs 立即模式

传统 GUI（Qt/MFC/WinForms）是**保留模式**：你创建一个按钮对象，
它常驻内存，框架替你保管、在合适时机重绘，你通过信号/事件回调响应。

ImGui 是**立即模式**：没有常驻的控件对象。每帧从零开始，
你的代码被调用时**当场描述**这一帧长什么样：

```cpp
mainWindow.setUI([&] {
    if(ImGui::Button("点我"))     // 每帧都执行：画出按钮、检测点击
        ++clicks;                 // 点击的那一帧返回 true，其余帧都是 false
    ImGui::Text("点击 %d 次", clicks);
});
```

`ImGui::Button` 这一行，一秒钟内执行了几十上百次。它不是"创建按钮"，
而是"这一帧把按钮画在这里，顺便告诉我它这一帧是否被点击了"。

**推论**：

| 特性 | 含义 |
|---|---|
| 没有内存泄漏问题 | 控件不驻留，帧结束即消失 |
| 状态在你手里 | 库只管外观与命中检测；`clicks`、文本内容、开关状态都是你的变量 |
| UI 结构每帧可变 | `if` 包住一行代码 = 该控件这一帧存在/不存在 |
| "回调"就是 if | 不注册监听器，直接在调用处检查返回值 |

## §2.2 状态必须活过每一帧

立即模式最经典的错误：

```cpp
mainWindow.setUI([&] {
    std::string label = "你好";     // ✗ 每帧构造、每帧析构，看似没问题……
    ImGui::TextUnformatted(label);  // ✗✗ 如果把 label 的地址交给 ImGui，
                                    //    下一帧它已经不存在（悬垂）
    static int n = 0;               // static 也能用，但多窗口/重入时不友好
    ++n;
});
```

配套程序 §2.2 区并排演示了**错误写法的后果**（用注释掉的对照）与正确写法。
规矩只有一条：

> **每帧 UI 使用的状态，定义在 setUI 回调之外，且存活期覆盖 `run()`。**

```cpp
int clicks = 0;                  // main 的栈上：活过 run()
std::array<char, 128> buf{};     // 输入框缓冲区同理（第 06 课）

mainWindow.setUI([&] {
    ImGui::Text("点击 %d 次", clicks);   // ✓ 只是读/写外部变量
});
```

`setUI` 捕获 `[&]` 按引用捕获，这些变量只要在 `main`（或长期存活的对象）
里，就天然满足契约。第 03 课的控件树、第 04 课的"状态外置"，本质都是
这条规矩的工程化。

## §2.3 setUI 的契约

```cpp
void Mk::window::setUserUI(std::function<void()> ui);
```

- **调用时机**：每帧一次，在窗口的 fullscreen 宿主窗口内、
  `ImGui::NewFrame()` 之后、渲染提交之前。
- **存活契约**：`std::function` 拷贝持有你的 lambda；lambda 按引用
  捕获的变量必须活到窗口销毁（准确说：到 `run()` 结束最后一次调用）。
- **可多次调用**：后一次覆盖前一次（在 `setUI` 里做 wg 树布局就是这样——
  把 `layout()` 包成 lambda 交给 setUserUI，见第 03 课）。

## §2.4 每帧重建 vs 构造一次：两种库的分工

mkui 的模板控件体系 `Mk::wg` 是立即模式的工程化路线：

| | `Mk::wg` 模板控件（第 03 课起） |
|---|---|
| 控件是什么 | 模板 struct（数据 + 功能函数），零继承 |
| 树结构 | 编译期 tuple 子组合 + 运行时 add/remove（墓碑） |
| 布局 | 两遍布局：measure（求期望）→ arrange（分配 bounds）→ draw |
| 适合 | 声明式组装 + 动态增删、长期存活的对象树 |
| 状态 | 控件持引用绑定外部变量 | 同样外置（库不藏状态） |

两套库可以互操作（第 10 课）。**没有"官方推荐"**——按场景选，
甚至同一窗口混用。

## §2.5 实验观察（配套程序）

程序分四区，都是 §2.1-§2.2 概念的活演示：

1. **计数器**：点击的那帧 `Button` 才返回 true——注意计数增长"一帧一次"。
2. **条件渲染**：勾选框控制一行文本"这一帧是否存在"（`when` 修饰器的原型）。
3. **正弦驱动**：进度条的值来自每帧重算的正弦——你什么都没"更新"，
   它自己就在动，因为每帧都是重新计算重新画。
4. **输入框缓冲**：`std::array` 外置缓冲，输入内容跨帧保留（状态在你手里）。

## §2.6 常见错误

1. **悬垂**：把局部 `std::string`/`const char*`（指向临时）交给会保存指针的
   API。规矩见 §2.2；第 04 课会讲库层面如何用"持字符串副本"根治。
2. **在 setUI 里改树后又当帧依赖**：多数情况 mkui 已处理（墓碑机制，
   第 03 课），但跨窗口副作用要自己注意时序。
3. **以为 Text 有"更新"API**：没有。想改显示内容就改你自己的变量，
   下一帧自然显示新值。
4. **把重活写进 setUI**：它每帧执行！文件 IO、网络请求放线程里
   （第 11 课的对话框就是这么做的），回调里只做轻量同步。
